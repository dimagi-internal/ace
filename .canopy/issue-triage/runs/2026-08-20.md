## Premise checks — the load-bearing part of this run

Three of eight issues did not survive contact with the code, and a fourth was half stale.
That is the ratio worth watching.

- **#1511** claimed Phase 2 is unique in running producer and eval in one subagent, and
  that Phase 3 dispatches evals separately. `grep -c 'Agent(' agents/commcare-setup.md`
  returns **0**, and `agents/commcare-setup.md:728` says "**Run the eval inline
  (preferred)**". `agents/ace-orchestrator.md:1527` makes in-context eval the architecture
  for all ten phases. It also misread "out-of-chain", which `skills/_eval-template.md:24-46`
  defines as a property of the grading *anchor*, not the grader's execution context. What
  was left applies to every ACE capability — the residual shape Jon closed #1466/#1468 for.

  the ceiling is "roughly 7.6-7.8 against a 7.5 threshold". Recomputing the real scores
  reproduces the reported 7.14 exactly, and fixing the two dimensions the issue itself
  concedes were genuine findings yields **7.515 → pass** with the "pinned" viability scores
  untouched. Both proposed remedies are prohibited in writing by
  `skills/_eval-template.md:59-64` (the deferral-exemption anti-pattern) and by the fixture
  brief's own "do not weaken the eval" clause.
- **#1500** was fully fixed at HEAD by PR #1502 and PR #1513; it stayed open only because
  those PRs used `Refs`-style wording rather than a close keyword.
- **#1289**'s title clause ("connect-resume-opp never got the #647 recalibration") is stale
  — that landed in PR #1475 (`0bac8047`) and is ratcheted by
  `test/mcp/mobile/static-recipe-invariants.test.ts:1391`. Its prior `blocked` verdict
  rested on a device visit the issue body itself records having already happened.

## Two places the vetted fix improved on the issue's own proposal

- **#1516** named `~line 1119` (`[Auth liveness]`) as where the fix lands. But `--preflight`
  does `exit 0` at `bin/ace-doctor:438`, so a probe added only there would not run in
  `/ace:run` and the timing would be exactly as blind as today. The fix wires **both**
  points and adds a static test asserting the preflight call site sorts before the exit —
  which structurally prevents someone "fixing" this the way the issue described.
- **#1487** proposed a new `fixture: true` field on `opp.yaml`. The fixture signal already
  exists at the opp root as `iterate-state.yaml` (`lib/opp-root-files.ts:106-114`), so the
  helper keys off that instead of adding a parallel marker.
