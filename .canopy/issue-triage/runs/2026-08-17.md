## The rule was the finding

The operator's hypothesis was that the device-validation rule was manufacturing
a backlog rather than catching drift. Two of the eight issues proved it, and
neither was a marginal case:

**#972** sat behind a "blocked on a live device" comment that was **false on the
day it was written** — the surfaces it named had shipped 16 days earlier. The
actual remaining work was *text*: a recipe header declaring a surface UNVERIFIED
that its own sibling recipe, in the same directory, had already recorded as
observed. Nothing in the change was sent to a device or matched against one.

**#1289** — the only `blocks-e2e` issue in the backlog — carried its device
evidence **inside the issue body**. The exact budget had been run on-device on
2026-08-14; the scroll and assert both COMPLETED and the Learn leg walked to
green. It then waited three days for a device it had already been to.

Neither premise had been re-read across two prior triages. That is the shape of
the cost: not bad changes shipping, but known-good changes sitting, under a verb
nobody re-examined.

The amendment (PR #1478) makes three changes and leaves the underlying principle
alone: recorded device evidence *is* device evidence; a nameable residual may be
merged with the residual named; a stale block is not a block. "Close the loop to
the source of truth" — don't guess a value another system owns — stands
untouched. The device gate was only ever an instrument of it.

## Cluster: stale-citations (#972, #1181, #1467)

Three issues, one shape: **ACE asserting something false about another system or
about itself, in a doc that keeps shipping.** In each case the *code* was fine.

- #1467's `deepMerge` was correct and had a passing test the whole time; three
  author-facing surfaces described `deep` as safe for the case it breaks — and
  `app-hq-settings` carried the *inverse* falsehood, which is worse, because a
  wrong mental model transfers to the next caller even when the instruction is
  right.
- #1181's claim cited a real upstream issue, which is exactly why the existing
  `predictive-guard-citation` ratchet passed it: that ratchet asks whether a
  citation *exists*, not whether it is *true*. Upstream then disproved it with
  request logs, and nothing re-read the citation.
- #972's stale-atlas citation was the same failure keyed on a version number.

So the preventers are two ratchets that fail when a citation *stops being true*:
citation-currency against `DEFAULT_APK_VERSION`, and an offline refuted-upstream
list. The first immediately found two more instances the issue never named.

## Judgment calls

**Every ratchet was proven red before shipping.** Each new guard was tested by
reverting the fix it protects and confirming failure, then restoring. A ratchet
that cannot go red is not a ratchet, and three of the four here were written in
the same session as the fix — the case where a self-passing test is easiest to
write by accident.

**#1110's threat model is recorded as low-to-medium, not "security = high."**
The injection vector is real — `/ace:turn` triages inbound external email and
the MCP subprocesses hold prod credentials — but MCP-argument sandboxing is not
the boundary that stops it, because the same agent holds an ungated `Bash` tool
and can read and exfiltrate a session file without touching an atom. The shipped
guards are accident rails and defense-in-depth. Stated on the issue so it can be
disagreed with.

**#1289 was shipped as (a), the budget raise, and (b) was recorded as tried and
insufficient.** `connect_delete_unaccepted_flw_invites` excludes accepted
invites, so it cannot touch the ~20-card In Progress section that supplies most
of the scroll depth, and soft-deactivation doesn't remove tiles either. Writing
that down matters more than the budget change — it stops (b) being re-proposed
as the obvious fix next time.

**#1395 was left open on its third identical triage.** The in-repo half shipped
in PR #1416; what remains is a product call on a funder-facing artifact that
lives in Drive and labs. Flagged explicitly as human-blocked so a fourth triage
doesn't re-derive it — and closing it as not-planned was offered as a legitimate
answer.

## Addendum: two operator decisions after the report

**#1395 — closed as not-planned, and the reasoning generalizes.** The question
was "should there be a repo issue for a run-specific thing?" No. The ACE tracker
is for code and harness; a defect in one run's narrative artifact is run state,
and it lives in Drive and labs workflow 5125 where this repo can't reach it.
Keeping it open produced a permanently-unactionable item that three consecutive
triages each re-derived at full cost. The generalizable half had already shipped
(PR #1416). What survives the close is routing, not loss: scene edits belong in a
DDD iteration on the narrative, and the narration-numbers ↔ plotted-values
checker belongs in **canopy** — filed there with two real YAMLs when they exist,
where it is actionable in a way it never was here.

**#1461 — built the same session, and the plan was wrong in one place.** The
triage said "apply the same fallback to `getProgram` in the same PR." Reading
upstream showed that isn't possible: every program route (`init/`, `<pk>/edit`,
`<pk>/view`) sits behind `ProgramManagerMixin` (is_admin AND program_manager),
and `program/urls.py` has no read-only detail route at all. Program metadata
isn't exposed below that tier, so a fallback parser would have had to invent its
source — the exact "ship another plausible guess" failure CLAUDE.md warns about.
Its 403 now names the requirement and remedy instead.

Two things worth carrying forward from that build:

- **The template beat a live probe.** The issue asked for live verification of
  the detail page's HTML before landing a parser. Reading `dashboard.html` and
  `get_context_data` is the stronger form of the same discipline — a capture
  says what one page looked like once; the template says what every page always
  renders. Same reasoning as ace#1236's `Orchestra.class`.
- **`HttpError` truncates at ~250 chars, so remedies must be front-loaded.** The
  first draft of the `getProgram` error buried its fix past the cut. Its own
  test caught it. Worth remembering for every operator-facing error in the
  backend.
